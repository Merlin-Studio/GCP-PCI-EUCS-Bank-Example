# 2-security-edge

Security controls that are one per project, created by the landing zone in
the projects the application stages deploy into. Apply after
`2-project-factory`, as the security stage's identity.

## Cloud Armor

The policies the security page defines, created in every project that can
host a backend service. Front doors attach them by name, and a backend service
can only use a policy in its own project. Re-apply whenever the rules on the
security page change.

| Policy | Rules | Projects |
|---|---|---|
| `compliance-waf-policy` | 4 WAF, adaptive protection | `app-dev-0`, `app-prd-0`, `app-stg-0`, `gke-dev-0`, `gke-prd-0`, `gke-stg-0` |

## Binary Authorization

A project has exactly one Binary Authorization policy. Each application
project gets it here, with one attestor, `signed-images`, that every
application in the project signs its images for. The application stages ask
their Cloud Run services to be evaluated against it and create nothing of
their own.

| Project | Attestor | Enforcement |
|---|---|---|
| `app-dev-0` | `signed-images` | dry run until you enforce |
| `app-prd-0` | `signed-images` | dry run until you enforce |
| `app-stg-0` | `signed-images` | dry run until you enforce |
| `gke-dev-0` | `signed-images` | dry run until you enforce |
| `gke-prd-0` | `signed-images` | dry run until you enforce |
| `gke-stg-0` | `signed-images` | dry run until you enforce |

The attestor trusts a key that is yours. Create the key, add its public key to
the attestor, and sign images for it in your pipeline. Until then the policy
only logs what it would refuse. Once every image is signed, set
`enforcement_mode = "ENFORCED_BLOCK_AND_AUDIT_LOG"`.
